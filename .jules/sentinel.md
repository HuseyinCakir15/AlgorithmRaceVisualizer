## 2026-07-25 - Information Exposure in Error Responses
**Vulnerability:** The Spring Boot backend lacked a global exception handler. When an exception occurred (e.g., passing an invalid algorithm name to the API or an oversized array), the server returned a raw `500 Internal Server Error` with stack traces and internal application details exposed.
**Learning:** This is a classic example of "Missing error handling exposing stack traces" and failure to "Fail securely". Unhandled exceptions allow malicious actors to probe internal implementations and gather information about the environment, libraries, and application logic.
**Prevention:** Always implement a centralized `@RestControllerAdvice` (or `@ControllerAdvice`) in Spring Boot applications to intercept and sanitize exceptions before they are returned to the client. Ensure exceptions are logged locally for debugging but transformed into generic, sanitized messages (like "An unexpected error occurred" or "Invalid input data provided") for external clients.
